# Architecture

This document records the decisions Open RT Studio is built on. Change it in
the same pull request as any change that contradicts it.

## Purpose and audience

Open RT Studio is imaging software for radiotherapy. It serves three groups
equally: researchers, clinic contouring and review workflows, and education.

It is **not for clinical use**. The app and the README carry an explicit
notice, and the app requires the user to acknowledge it before the viewer opens.

## Decisions

| Topic | Decision |
| --- | --- |
| License | MPL 2.0. Wide adoption, with changes to our files kept open. |
| Web client | Angular 22: standalone components, zoneless, signals with `OnPush`. Rendering with WebGPU and WGSL. |
| WebGPU | We stay on WebGPU. A WebGL2 fallback is a possible later addition, not planned work. When WebGPU is missing the app explains why and what to do. |
| Desktop | Electron for macOS, Windows and Linux, hosting the same web client. It must also work standalone with no server. |
| Server | TypeScript on Node. The same server core runs inside Electron's main process for standalone mode. |
| PACS | Our own: filesystem storage, an RT-aware index on SQLite (standalone) or PostgreSQL (servers). We do not bundle Orthanc because it is GPL/AGPL. Orthanc and DCMTK tools may be used as test peers in CI only. |
| DICOM networking | DIMSE-C send and receive (C-ECHO, C-STORE, C-FIND, C-MOVE, C-GET) with configurable remote AE titles, using a permissively licensed protocol library. We do not write the protocol from scratch. |
| Heavy compute | C++ command-line programs built on ITK and elastix, started as jobs by Node and bundled into desktop installers. No Python at runtime. |
| GPU-side work | Applying a registration (image resampling through a deformation field, dose warping and summation) can run in the client on WebGPU. The server is needed only to compute registrations. |
| AI models (later) | ONNX Runtime, to avoid a Python runtime. |
| Hosting and CI | GitHub Actions on Linux, macOS and Windows runners. Web client on GitHub Pages, installers on GitHub Releases, server container on GHCR. |
| Test data | Synthetic or clearly shareable public data only. Never commit patient data. |

## Repository layout

The repository is one npm workspace.

```
apps/web            Angular web client
apps/desktop        Electron app (planned, M2)
services/server     Node server and PACS (planned, M2)
packages/dicom      DICOM parsing, volumes, structure sets, catalog
packages/render     WebGPU rendering and pure geometry helpers
packages/testdata   Synthetic DICOM, RTSTRUCT and RTDOSE generators
native/             C++ ITK/elastix tools (planned, M3)
docs/               This document and policies
scripts/            Repository checks
```

Dependency rules:

- `packages/dicom` depends on nothing in this repository. It must run in a
  browser, in a web worker and in Node, so it uses no Angular, DOM-only or
  Node-only APIs.
- `packages/render` depends only on `packages/dicom` and WebGPU types.
- `packages/testdata` depends on nothing in this repository.
- `apps/*` and `services/*` may depend on any package. Packages never import
  from apps or services.

Packages are consumed as TypeScript source. Each package exposes its modules by
subpath (`@open-rt-studio/dicom/volume`), and the consuming app's bundler
compiles them. There is no separate build output for packages.

## Web client patterns

- State is held in `signal()`, derived with `computed()`, and side effects run
  in `effect()`. Signals are updated immutably.
- Per-orientation state is an `[axial, coronal, sagittal]` tuple indexed by the
  `Orientation` enum.
- `switch` statements on enums are exhaustive, with a `never` default, so adding
  a member fails to compile until it is handled.
- The slice shader and the CPU-side probe implement the same geometry from
  opposite directions. Change them together; shared geometry lives in pure
  helpers that both use.
- Pure logic lives in `packages/` and is unit-tested there without a GPU.

## Testing

- Unit tests are colocated `*.spec.ts` files run by Vitest.
- Browser tests use Playwright with synthetic data.
- CI runners have no GPU. Tests that need WebGPU must detect its absence and
  skip those assertions explicitly instead of failing.

## Privacy

- Application logs never contain patient identifiers.
- Paths and file names generated by the software never contain patient
  identifiers.
- Test fixtures are generated; see `packages/testdata`.
